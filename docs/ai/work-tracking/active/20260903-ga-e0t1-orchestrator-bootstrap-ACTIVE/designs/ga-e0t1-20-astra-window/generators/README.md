## Explicit differences from the old Template window

- BIND validates the real nonblocking parent edge and own task fields rather
  than treating changing embedded parent history as worker authority. It binds
  only gc.work_dir plus an exact hash-bound startup-contract note. Full raw
  Bead snapshots and exact before/after deltas are retained.
- The two exact installed ignored policy files are admitted; arbitrary ignored
  files, scope changes, metadata overrides and a second worker still refuse.
- Suspension may display one census-bound worker twice, once under its native
  session name and once under its canonical agent. Resume does not inherit
  this exception. Duplicate sessions, wrong workspace/provider/counts refuse.
- S5's already-consumed stranded-lifecycle acceptance and five historical
  disposition paths are not reused as authority for this new window.
- Early WATCH uses the same bounded read-time accounting as final preservation.
  It changes comparison copies only, never timestamps or source metadata.
- worker-startup.py tests in the actual worker sandbox, not the coordinator:
  pristine base/branch, managed session identity, exact policy and binary,
  subscription auth, owned workspace write and a sacrificial denied write.
  An unexpectedly successful negative leaves its marker intact and fails.
- A separate literal gpg version request must be denied by the native policy.
  The worker waits for a session-bound source release after STARTUP READY.
  This is not a typed receipt, signing proof or provider-parity claim.
- The post-terminal candidate status parser admits only unstaged changes to
  the three source files, the two unchanged policy files and separately bounded
  evidence. Staging, deletion, rename, extra source and path escapes refuse.

## Preserved design checklist and current review boundary

1. Implemented startup-release integration compares live session/claim,
   process argv and ancestry, effective policy/trust, actual native denial,
   probe report and unchanged source before one supported same-session nudge.
   The worker-side report alone must never authorize source edits.
2. Implemented post-terminal read-only candidate inspection includes regular-file
   evidence bounds, policy hashes and exact common-Git preservation. Only after
   independent candidate review may the coordinator intake or deliver its patch.
3. Bind the final exact cache disposition after a complete current-state
   comparison. Do not copy the old window's accepted timestamp or normalize
   unrelated drift. C1's later operator-bound disposition remains separate.
4. Explicit final-candidate assembly removes the deliberate
   draft barriers as part of preparing the final execution candidate. Exercise
   its consolidated tests, preserve all failure evidence, sign the clean final
   candidate, and obtain two fresh request-bound Astra reviews. Queue only
   those exact reviewed bytes. Never change a barrier or pin after review and
   reuse the earlier verdicts.

No new root, privilege, worker service, task database, permission exemption or
Claude invocation is introduced. The product source remains for Gas City.

root as an external source-work root. Do not rewrite its registry to pass that
check or claim the worker has Aegis coordinator readiness. The existing managed
candidate lane has its own explicit root and claim contract. On this Linux
worker account there is no installed gas-city-workflow plugin, and this base

These are configuration observations, not proof that native trust/rules load.
The actual startup and negative-policy checks above are still mandatory. If a
real hook or trust check refuses, report it and contain; never bypass it.
