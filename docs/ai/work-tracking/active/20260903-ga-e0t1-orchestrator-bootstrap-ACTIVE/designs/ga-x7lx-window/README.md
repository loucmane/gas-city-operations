## Why a successor

The ga-sh3w window ran on 2026-09-26 and passed every job from EXCLUDE through TERMINAL. Core started the candidate
(`ci-o1zvn`) with the exact P10 argv, and it claimed ga-sh3w itself. At 10:15:12Z it closed the task with
`gc.failure_class bead_brief_unreadable`, before making any edit:
- `bd show ga-sh3w --json` printed 51.9K characters: the 33K description plus the embedded related ga-fsfg
  record (14.8K);
- that is over the candidate's Bash inline limit, and the overflow file under `~/.claude` is denied by the
  candidate policy;
- a sandboxed redirect cannot reach Dolt.

The candidate policy held. The worktree stayed clean, the common git directory was unchanged, and INTAKE had
nothing to import. The consumed worktree was retired afterwards: `intake.py retire` archived and locked it under
`candidate-archive/ga-sh3w`.

**Operator decision (2026-09-26 12:35 CEST): split the brief into small Beads.** The reviewed r12 R3 brief
(`5cbf64f1`) is unchanged and split verbatim:
- **ga-x7lx**, the task (2.2K). It holds the brief head (role, goal, scope rules) and the working rules, plus a
  pointer that makes the two spec holders part of the brief and tells the worker to stop if either read is
  truncated. It has no dependency edge, so `bd show` embeds no other record.
- **ga-lpo2**, spec part 1 (12.8K): new profile fields, where the existing classes live, how the gate reads git,
  and the closed grammar for push, PR and merge.
- **ga-r2el**, spec part 2 (18.9K): every approval, and the acceptance list.

Both spec holders are closed chores labelled `r3-spec`. The head, both parts and the tail reassemble byte for
byte to the r12 brief. The largest `--json` view is 20.1K. The brief names the `--json` form, because the plain
view of ga-r2el is 32.7K. The evidence is in `reports/r3-brief-split-20260926` (split.py and the live reads).
