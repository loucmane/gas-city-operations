## Failure and replay

Known failure validates every current postimage and journal before any restore.
Leaf rollback precedes reverse renames. An unexplained writer, unexpected child,
pending prior attempt or rollback mismatch stops without blind repair. Abrupt
interruption remains pending; there is no automatic resume.

Immediately after success, exact reapplication proves a read-only no-op: accepted
images, backups, plan and documentation proof must agree; Go and plan-sync are
not rerun. Do this before later logging advances state. Locks serialize cooperating
local callers; they are not distributed reservations or kernel no-replace rename
primitives. No rig, provider, service, waiver, source-content or key operation is
included.
